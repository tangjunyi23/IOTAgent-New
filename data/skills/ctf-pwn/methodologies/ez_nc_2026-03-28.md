# CTF Pwn Methodology: ez_nc

**Date**: 2026-03-28
**Binary**: `ez-nc`
**Architecture**: `x86_64`
**Mitigations**: `NX`, `Full RELRO`, `PIE`, `No Canary`, `SHSTK`, `IBT`
**Vulnerability Class**: `format string in filename synthesis`
**Primitives**: `stack leak`, `stack argument discovery`, `format-string-driven filename synthesis`, `remote binary recovery`, `static flag extraction`
**Reuse Tags**: `fmt`
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- Goal: solve the remote-only service at `nc1.ctfplus.cn:49517` without a bundled ELF.
- Local artifacts used: a remotely recovered copy of the PIE binary (`remote_bin.bin`) plus `objdump`, `strings`, and live socket interaction.
- The headless IDA export wrapper was attempted after recovering the ELF, but it failed with `idat_exit_code=1`, so the solve continued from disassembly.

## 2. Ground Truth

- Runtime probing showed the service prompts with `Enter the filename to download: ` and reads only 7 bytes per request because it uses `fgets(buf, 8, stdin)`.
- Blacklist checks reject only substrings `ez-nc`, `proc`, and `%c`.
- Disassembly proved the core bug in `main`:
  - input lands in the 8-byte stack buffer at `[rbp-0x10]`
  - `snprintf(dst, 0x58, user_input)` is called directly with attacker-controlled format text
  - the formatted destination buffer is then passed to `fopen`
  - only the error path is safe: `printf("%s not existed or could not be opened.\n", resolved_path)`
- Runtime evidence from `%<idx>$p` showed that deeper positional arguments reach the initial process stack. `%45$s` resolves to a stack-resident startup path and makes the service open and stream its own PIE ELF.
- `strings -a -tx remote_bin.bin` and `.rodata` inspection showed an unreferenced flag literal at offset `0x2008`: `polarisctf{fb87918b-5f67-4613-9ef0-cac2d4da1471}`.

## 3. Exploit Chain

- Stage 1: treat the format-string bug as a filename oracle instead of chasing `%n` first.
- Stage 2: send `%45$s`; `snprintf` formats a startup-stack pointer into the destination path, and `fopen` returns the current executable.
- Stage 3: save the streamed ELF locally and extract the unused flag string from `.rodata`.
- Decisive insight: the vulnerable `snprintf(dst, size, user_fmt)` sits before `fopen`, so `%45$s` is enough to synthesize the executable path and bootstrap attachment recovery from a remote-only service.

## 4. Dead Ends Worth Remembering

- Route attempted: treat the service as a plain file-reader with path traversal or command injection.
- Why it failed: the 7-byte `fgets` limit prevents long paths, there is no shell expansion, and `/proc` is blacklisted.
- Earlier signal that should have warned about the failure: error messages turned `%p` into live leaks, proving the interesting bug was format processing rather than path sanitization.

## 5. Lessons to Reuse

- Signals to watch for:
  - tiny filename buffers paired with `snprintf`, `printf`, or other format-capable builders before `open` or `fopen`
  - blacklist logic that blocks `%c` or `/proc` but leaves `%s`, positional specifiers, and deeper stack indices intact
  - remote-only services where recovering the missing ELF is more valuable than forcing a blind write primitive
- Mitigation mix:
  - Full RELRO, PIE, SHSTK, and IBT did not matter because the shortest route never needed control-flow hijack.
  - The lack of a canary was irrelevant once the format-string path synthesis exposed the attachment directly.
- Reusable trick:
  - when attacker input becomes the format string for `snprintf(dst, size, user_fmt)` and the output becomes a filename, positional `%s` can turn startup stack pointers into real paths; this is often faster than pursuing `%n`.
- Should `patterns.md` be updated: yes. Add the generalized lesson about probing high positional `%s` indices for `argv[0]` or environment-backed path strings when a format string is used to build filenames.
