# CTF Pwn Methodology: pwn-ph

**Date**: 2026-03-28
**Binary**: `vuln.so` PHP extension plus `readflag`
**Architecture**: x86_64
**Mitigations**: NX, PIE, Partial RELRO (`vuln.so`), Apache `mod_php` 8.1
**Vulnerability Class**: signed index OOB in extension metadata access plus stale heap globals
**Primitives**: cross-request base leak via uploaded PHP, negative-index arbitrary `.data/.bss` write, GOT overwrite to `system`, root flag exfil via shell redirection
**Reuse Tags**: signed-index, ret2libc
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- The web entrypoint was `index.php`, which allowed arbitrary filename upload into `/var/www/html` and direct execution of uploaded `.php`.
- Local artifacts were `Dockerfile`, `index.php`, `php.ini`, `vuln.so`, and the SUID `/readflag` helper copied to the image root.
- Remote ran `php:8.1-apache`; `PHP_SAPI` was `apache2handler`, many PHP functions were disabled, and `FFI` was unavailable.
- `/proc/self/maps`, `/etc/os-release`, and `/var/lib/dpkg/status` were still includable through PHP `include()`, which gave stable code bases and the exact remote libc package version `2.41-12+deb13u1`.

## 2. Ground Truth

- Disassembly proved `add`, `edit`, and `delete` only checked `idx <= 0xf` and never enforced `idx >= 0`.
- In all three handlers the index stayed signed through the final addressing mode, for example `mov rdi, [rax+rsi*8]` in `zif_edit` and `zif_delete`.
- The extension stored its globals in nearby writable memory:
  - `heap_size` at `base+0x4180`
  - `heap` at `base+0x41c0`
  - a self-pointer relocation at `base+0x4080`
  - `_efree@got` at `base+0x4050`
- `edit(-40, payload)` was the key bootstrap because `heap[-40]` dereferenced the self-pointer at `base+0x4080`, so the copy destination became writable `.data` inside `vuln.so`.
- Runtime verification showed `edit(-40, ...)` could rebuild `.data/.bss` and zero `heap[12]`; a follow-up `edit(12, "A")` then printed `Index 12 is not allocated`, proving arbitrary overwrite of extension metadata.

## 3. Exploit Chain

- First upload a tiny PHP file that includes `/proc/self/maps` and parse `vuln.so` plus `libc.so.6` bases externally.
- Reconstruct `vuln.so` runtime bytes for `0x4080..0x4240`, reapply the relocation-dependent qwords, zero the `heap[]` and `heap_size[]` arrays, then patch:
  - `heap_size[0] = 8`
  - `heap[0] = vuln_base + 0x4050` (`_efree@got`)
- Call `edit(-40, hex2bin(payload))` to rewrite that region in one shot.
- Call `edit(0, p64(libc_base + 0x53110))` to replace `_efree@got` with `system`.
- Allocate a clean command chunk with `add(1, 0x80)` and write `/readflag > /var/www/html/<random>.txt\0`.
- Trigger `delete(1)`, which now executes `system(command)`.
- Read the generated file back over HTTP to recover the flag.
- Decisive insight: the shortest route was not the PHP heap double-free at all; it was the missing lower-bound check on `idx`, and `edit(-40)` turned the extension’s own self-pointer relocation into a stable arbitrary write.

## 4. Dead Ends Worth Remembering

- Double-free plus forged `zend_string` overlap was real and useful for heap leakage, but it was not the shortest path once the signed index bug was noticed.
- Naive freelist poisoning onto GOT targets did not pay off quickly; the allocator route was much noisier than the direct negative-index overwrite.
- Replacing `_efree` with `puts` proved that child-process or libc stdout under `apache2handler` did not appear in the HTTP body, so `system("/readflag")` alone would not exfiltrate the flag.
- The earlier warning sign was the assembly itself: every handler used `jg 0xf` with no lower bound, which should have moved the investigation to negative indices immediately.

## 5. Lessons to Reuse

- If an index into global pointer tables is only upper-bounded and later used as a signed scaled address, compute the negative indices before spending time on allocator corruption.
- In PIE shared objects, relocation-generated self-pointers inside writable `.data` can bootstrap an arbitrary write even when direct GOT writes are not reachable in one step.
- For webserver-embedded code execution, verify where `system` output goes before relying on it; shell redirection into a web-accessible file can be more reliable than stdout.
- Should `patterns.md` be updated: yes. Add a reusable `signed-index` pattern for missing lower-bound checks on scaled array accesses into adjacent globals or relocations.
