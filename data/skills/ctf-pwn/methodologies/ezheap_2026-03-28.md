# CTF Pwn Methodology: ezheap

**Date**: 2026-03-28
**Binary**: inference_forge
**Architecture**: x86_64
**Mitigations**: NX, PIE, Full RELRO, Canary, FORTIFY, SHSTK, IBT, seccomp
**Vulnerability Class**: heap integer truncation plus heap overflow plus UAF
**Primitives**: tiny-chunk heap overflow into adjacent scheduler control, stale-session tcache poisoning, arbitrary allocation onto task descriptor, indirect call to built-in flag reader
**Reuse Tags**: heap-overflow, uaf, tcache, seccomp
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- Goal: recover the flag printed by the binary's internal audit path instead of trying to spawn a shell.
- Local artifacts used: `inference_forge`, bundled `libc.so.6` (`Ubuntu GLIBC 2.39-0ubuntu8.7`), bundled loader, `seccomp.json`.
- Remote endpoint: `nc1.ctfplus.cn 13251`.
- Headless IDA export was attempted first and failed because the local IDA installation had no valid license, so the solve used `objdump`, `strings`, and runtime evidence.

## 2. Ground Truth

- The binary is a stripped PIE C++ ELF with Full RELRO, canary, NX, SHSTK, and IBT.
- The seccomp profile blocks `execve` / `execveat`, `ptrace`, `bpf`, and `kexec*`, so shell-centric routes are the wrong default.
- `option 1` multiplies attacker-controlled `items * stride` twice: a 64-bit `declared_bytes` and a truncated 32-bit allocation size. `65536 * 65536` produces `declared_bytes = 0x100000000` but allocates only `0x20`.
- `option 2` bounds writes against `declared_bytes` instead of the real allocation and allows offsets up to `0x5f`, so the tiny artifact becomes a reliable 0x40-byte heap overflow.
- Runtime telemetry proved a decisive heap layout: if the tiny artifact is allocated before bootstrapping the scheduler, `artifact.arena` and `scheduler.ctrl` are separated by exactly `0x30`. Writing one byte at `artifact + 0x38` flips `scheduler.ctrl + 0x8`, which disables the handler whitelist.
- `option 5` allocates a `0x50` session object, `option 6` frees it but keeps the stale pointer, and `option 7` rewrites qword 0 of that freed chunk. With two freed sessions, this becomes safe-linking-aware tcache poisoning for the `0x60` bin.
- `option 8` allocates another `0x50` object and writes parsed decimal qwords at offsets `0x0`, `0x8`, `0x10`, `0x18`, `0x20`, and `0x48`, plus a string at `0x28`. That layout matches the scheduler task descriptors created by `option 3`.
- `option 9` dispatches a task by calling `desc->handler(desc->ctx)`. `diag.audit_sink` from telemetry points at a built-in function that opens `./flag` and then `/flag`, reads one line, and prints it as `[audit] snapshot: ...`.
- Disassembly of `audit_sink` showed that it does not meaningfully depend on the incoming `rdi`, so a null `ctx` is acceptable.

## 3. Exploit Chain

- Trigger the integer truncation with `items = stride = 65536` to get a `0x20` artifact chunk with a fake 4 GiB declared size.
- Bootstrap the scheduler after the artifact so `scheduler.ctrl` lands at `artifact + 0x30`.
- Use `option 2` with `offset = 0x38` and payload `00` to clear `scheduler.ctrl + 0x8`, disabling strict handler whitelisting.
- Allocate two sessions and complete them in order `slot 0`, then `slot 1`, so the freed `0x60` tcache bin becomes `slot1 -> slot0`.
- Leak `task0 desc` and `diag.audit_sink` from telemetry, leak the stale `slot1` handle from telemetry, and compute the poisoned next pointer as `desc0 ^ (slot1_handle >> 12)`.
- Patch freed `slot1` qword 0 with that encoded pointer using `option 7`.
- Call `option 8` twice:
  - first as a warm-up to consume the poisoned session chunk,
  - second to land on `task0`'s live descriptor and rewrite `handler = audit_sink`, `ctx = 0`, and the other descriptor fields with valid decimal values.
- Dispatch `task 0`; the binary now calls the built-in flag reader and prints the flag.
- Decisive insight: the shortest route is not “turn the UAF into RIP control directly”, but “use the artifact overflow to kill the scheduler whitelist, then abuse the fact that worker profiles and task descriptors share the same `0x50` field layout.”

## 4. Dead Ends Worth Remembering

- Direct session-postprocessor hijack was a trap. The session object is adjacent to the tiny artifact, but `option 6` only allows three whitelisted post-processing function pointers and falls back to the default for anything else.
- Poisoning `scheduler.ctrl` with the `option 8` reallocation looked tempting at first, but `ctrl` is smaller than the worker object. Once runtime telemetry proved the artifact-to-ctrl adjacency, a one-byte overflow was both cleaner and more reliable.
- Waiting for pseudocode would have been wasted time. The allocator sizes, field layouts, and call targets were fully recoverable from disassembly plus telemetry.

## 5. Lessons to Reuse

- If a menu challenge keeps both a “declared size” and an “allocated size”, immediately test for mixed-width arithmetic and compare them in runtime telemetry before doing deeper reversing.
- When a heap overflow seems too short to reach the obvious function pointer target, check whether it can instead hit a nearby policy byte or gate bit that makes a second primitive usable.
- If two different menu objects share the same allocation size and write the same qword offsets, treat that as a type-confusion-by-tcache-poisoning opportunity even when the program never explicitly frees the target object.
- In seccomped services, a built-in diagnostic or audit file reader is often a better final target than `system` or ORW-from-scratch.
- Should `patterns.md` be updated: no. The solve is very reusable as a heap methodology note, but the decisive layout coincidence is still challenge-specific rather than a new generic pattern.
