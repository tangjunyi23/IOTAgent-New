# CTF Pwn Methodology: attachment_30

**Date**: 2026-05-09
**Binary**: `notepad`
**Architecture**: x86_64
**Mitigations**: NX, PIE, No RELRO, Canary, SHSTK, IBT
**Vulnerability Class**: signed index out-of-bounds read/write in a global note table
**Primitives**: libc leak from copied stdio pointers, GOT overwrite via negative index, `system("/bin/sh")`
**Reuse Tags**: signed-index, ret2libc
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- The service is a tiny notepad menu with create and view actions and a 10-note global array.
- Local artifacts were `attachment_30/notepad` and a bundled `libc.so.6`; no loader was provided, and the bundled libc could not be executed locally with the host loader.
- Remote endpoint: `39.96.193.120:10005`.
- The bundled libc claimed `Ubuntu GLIBC 2.31-0ubuntu9.2`, but live remote leaks matched `Ubuntu GLIBC 2.31-0ubuntu9.18` instead.

## 2. Ground Truth

- `get_note` reads an `int`, checks only `idx <= 9`, and computes `notes + idx * 0x30`. There is no lower-bound check.
- `notes` starts at `.bss:0x35a0`, and each note is `{ char name[0x10]; char content[0x20]; }`.
- Negative indices land on nearby writable metadata:
  - `idx = -1` starts at `stdin` and `stderr` copy-relocated pointers.
  - `idx = -5` content covers `puts@got` and `__stack_chk_fail@got`.
- `view_note` uses `puts(note->name)` and `puts(note->content)`, so leaking `idx=-1` yields the low 6 bytes of the live `stdin` pointer.
- The decisive runtime proof was that a short `create(-5, ..., b"B"*0x10)` lets `view(-5)` print filler followed by the real `puts@got`, which exposed that the remote libc offsets did not match the bundled libc.

## 3. Exploit Chain

- Leak the remote `stdin` pointer with `view(-1)`.
- Use the live offset match for `2.31-0ubuntu9.18`: `_IO_2_1_stdin_ = 0x1ec980`, `system = 0x52290`.
- Create note `0` with name `/bin/sh`.
- Use `create(-5, ...)` to overwrite `puts@got` with `system`. Overwriting `__stack_chk_fail@got` with the same value avoids leaving an obviously invalid pointer in the adjacent slot.
- Trigger `view(0)`. The first `puts(note->name)` becomes `system("/bin/sh")`, and queued shell commands can immediately read the flag.
- Decisive insight: once `idx=-1` leaked `stdin`, the shortest route was not trusting the shipped libc but validating the live remote minor revision from a second GOT leak and then using the same negative index to turn `puts(name)` into `system("/bin/sh")`.

## 4. Dead Ends Worth Remembering

- Trying to run the bundled `2.31-0ubuntu9.2` locally with the host loader failed with `dl-call-libc-early-init` assertions.
- The first remote exploit attempt used the bundled libc offsets and replaced `puts@got` with the wrong `system`. The symptom was an infinite stream of `> ` prompts because `view(0)` returned to the menu and the queued shell command was reinterpreted as menu input.
- The earlier signal was the mismatch between bundled artifacts and runtime behavior: a second leak showed remote `puts` at offset `0x84420`, not the bundled `0x875a0`.

## 5. Lessons to Reuse

- If a note-table signed index reaches copy-relocated `stdin` or `stdout`, start by leaking libc there before spending time on PIE.
- When the challenge ships a libc but no loader, treat “local loader mismatch” and “remote minor revision drift” as likely. Confirm the live libc with a second leak before trusting symbol offsets for control-flow hijacks.
- Short reads are not only a hazard; they can be used intentionally to seed nonzero padding before a GOT slot and make `puts` leak the real function pointer.
- Should `patterns.md` be updated: no. The main lesson is challenge-specific validation of shipped-versus-live libc rather than a new general pattern.

## 6. Deliverables

- Exploit script: `attachment_30/exploit.py`
- Remote-specific adjustment: use Ubuntu GLIBC `2.31-0ubuntu9.18` offsets instead of the bundled `2.31-0ubuntu9.2` libc.
- Remaining assumptions: the exploit is remote-first; local execution was validated under the host libc for control-flow behavior, not under the exact remote glibc bundle.
