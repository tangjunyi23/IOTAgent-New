# CTF Pwn Methodology: pwn_ct

**Date**: 2026-03-28
**Binary**: nginx (proxy) + remote config-service
**Architecture**: mixed (aarch64 nginx, x86_64 Go backends)
**Mitigations**: nginx PIE, Full RELRO, Canary, NX, FORTIFY; static Go backend; route stayed in logic-land
**Vulnerability Class**: nginx alias traversal plus sed replacement-expression injection
**Primitives**: alias traversal to internal config, HS256 JWT forgery, authenticated command execution through GNU sed `e` flag
**Reuse Tags**: cmd-injection
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- Goal: recover the remote flag from the HTTP service at `http://80-670f02f3-f861-4a6b-81fa-ae2134396f9c.challenge.ctfplus.cn`.
- Local artifacts used: the supplied aarch64 `nginx` ELF plus `default.conf`, and the remote-downloaded x86_64 Go `config-service` and `log-service` binaries recovered through the nginx alias traversal.
- Headless export was attempted against the local `nginx` binary and failed with `Cannot continue without a valid license`, so the solve proceeded from config review, strings, and backend disassembly.
- The remote flag path `/flag` was confirmed live through injected command output.

## 2. Ground Truth

- `file` showed the provided proxy binary is a stripped aarch64 PIE `nginx`; `checksec` showed Full RELRO, Canary, NX, PIE, and FORTIFY. `strings` matched stock `nginx/1.18.0 (Ubuntu)`.
- `default.conf` contained the decisive proxy bug:
  - `location /static { alias /var/www/static/; }`
  - because the location prefix lacked a trailing slash while the alias kept one, `/static../app/config.yaml` resolved to `/var/www/static/../app/config.yaml` and leaked the JWT secret from `/var/www/app/config.yaml`.
- The leaked `config-service` binary was a statically linked, symbolized x86_64 Go ELF. `gdb` on that binary proved:
  - `main.sanitizeID` compiles `[^a-zA-Z0-9\\-]` and strips every non-alnum/hyphen byte before `filepath.Join(data_dir, device_id + ".conf")`, which kills direct traversal through `device_id`.
  - `main.sanitizeOldValue` only accepts `^[a-zA-Z0-9._\\- ]+$`.
  - `main.filterNewValue` only blacklists `;`, `$`, `(`, `)`, `&`, `>`, `<`, `!`, `\n`, `\r`, and `\\`, plus values longer than `0x80`.
  - `main.handleConfigUpdate` does not write a file back. It runs `sed` directly as `sed fmt.Sprintf("s#.*%s.*#%s#", old, new) config_path` and returns `CombinedOutput()` in JSON.
- The decisive runtime proof was a live `new_value = "ls /#e"` request. GNU sed treated the injected `#e` as the substitution `e` flag and returned the root directory listing in the `output` field.

## 3. Exploit Chain

- Stage 1: request `/static../app/config.yaml` and extract `jwt_secret: "iot-guardian-s3cret-key-2024"`.
- Stage 2: forge an HS256 JWT. Claims `sub=admin`, `role=admin`, `iat`, and `exp` were sufficient to satisfy the backend.
- Stage 3: use `/api/config/list` and `/api/config/view?device_id=cam-01` to recover a stable `old_value` such as `DefaultSSID`.
- Stage 4: send
  - `POST /api/config/update`
  - `{"device_id":"cam-01","old_value":"DefaultSSID","new_value":"cat /flag#e"}`
- The backend builds `sed 's#.*DefaultSSID.*#cat /flag#e#' /data/devices/cam-01.conf`. On GNU sed, `#e` promotes the rest of the replacement to a command, executes `cat /flag`, and substitutes the command output into the matching line.
- Because the service returns `CombinedOutput()` verbatim, the flag comes back in the JSON `output` field.
- Decisive insight: once the nginx alias mismatch leaked the JWT secret, the shortest route was not file traversal in the Go service but parser-level injection into its sed replacement string; `#e` turned a fake config-update helper into authenticated command execution.

## 4. Dead Ends Worth Remembering

- Route attempted: treat the supplied nginx binary as a custom memory-corruption target.
- Why it failed: both the local strings output and the live `Server:` header matched stock Ubuntu nginx; the challenge logic lived in configuration and hidden backends, not in the proxy ELF.
- Earlier signal that should have warned about the failure: `default.conf` already named internal services, the JWT file path, and the classic `alias` footgun.
- Route attempted: direct path traversal through `/api/config/view` or `/api/config/update` by abusing `device_id`.
- Why it failed: `sanitizeID` strips `.`, `/`, `_`, and every other non-alnum/hyphen byte before appending `.conf`.
- Earlier signal that should have warned about the failure: `info functions main.` exposed `sanitizeID`, which is usually worth disassembling before brute-forcing traversal payloads.
- Route attempted: shell-metacharacter injection through `new_value`.
- Why it looked blocked: `filterNewValue` blocks the obvious shell separators.
- Earlier signal that should have warned about the failure: the service uses `os/exec.Command("sed", expr, file)`, so the dangerous parser is sed itself, not the shell.

## 5. Lessons to Reuse

- Signals that should trigger this route early:
  - `location /name { alias /path/; }` with a missing trailing slash on the location block
  - backend "update" helpers that wrap `sed`, `awk`, `find`, or similar text DSLs through `exec.Command`
- Mitigation mix:
  - Full RELRO, PIE, canary, NX, FORTIFY, and static linking were irrelevant because the shortest path stayed entirely in logic-land.
- Reusable trick:
  - If a sed expression is built as `s#.*old.*#new#`, an unescaped `#` in `new` can terminate the replacement early and promote the remainder to sed flags; on GNU sed, `#e` is often enough to gain command execution plus reflected output.
- Should `patterns.md` be updated: yes. Add a `cmd-injection` lesson for parser-level injection into external helpers where the sink is the helper's own expression language rather than the shell.
