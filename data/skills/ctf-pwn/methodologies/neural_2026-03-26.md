**Date**: 2026-03-26
**Binary**: `engine`
**Architecture**: `x86_64`
**Mitigations**: `NX`, `Full RELRO`, `PIE`, `Canary`, `SHSTK`, `IBT`, `No seccomp observed`
**Vulnerability Class**: deterministic admin-key derivation plus VNM-assisted command-buffer overwrite
**Primitives**: public `pid`/uptime leak, admin token forgery, arbitrary dword write into `g_pwn+0x10`, root `system()` execution, file exfil via downloads

## 1. Snapshot

- Goal: exploit `http://60.205.218.124:26722` and recover the remote flag.
- Artifacts used: `neural/bin/engine`, `Dockerfile`, Flask frontend, and the raw `/api/raw` endpoint exposed by the web app.
- The remote endpoint looked like an `nc` target in the prompt, but the port actually served HTTP/Werkzeug. That mattered because the final exfil path was `/api/download`.

## 2. Ground Truth

- `engine` is a PIE amd64 ELF with `NX`, `Full RELRO`, stack canary, `SHSTK`, and `IBT`.
- `main` derives the 16-byte admin secret by calling `derive_admin_key(g_pid, g_start_time, g_pwn)`. There is no randomness beyond the process PID and startup timestamp.
- `/api/status` exposes the backend `pid` and `uptime`, and the HTTP `Date` header gives the server time. That makes `g_start_time = Date - uptime` recoverable remotely, so the full admin secret is reconstructible.
- `verify_admin_token` only checks that the caller-supplied timestamp is within 60 seconds of the current time, then verifies `SHA256(timestamp || subcmd || extra || g_pwn[0:16])`. Once `g_pwn[0:16]` is recomputed, admin access is gone.
- `handle_admin` uses subcommand `0x05` for diagnostics. It first runs `execute_vnm(payload, payload_len)` and then calls `system(g_pwn + 0x10)`.
- `g_pwn + 0x10` is initialized to `/opt/neuralchat/plugins/diag.sh`, and VNM opcode `0x07` performs a signed-offset 32-bit store to `g_pwn + 0x90 + off`. Because `off` is a signed byte, negative offsets reach `g_pwn + 0x10`.
- The one obvious non-admin memory bug was in `handle_upload_knowledge`: it trusts the client-supplied content length and can write stack over-read bytes into a file. That was real, but it was not needed once the public-telemetry-derived admin secret was confirmed.

## 3. Exploit Chain

- Query `/api/status` and parse the HTTP `Date` header.
- Recompute `start_time = server_time - uptime` and derive the first 16 bytes of `g_pwn` with the same xorshift-plus-SBOX routine used by `derive_admin_key`.
- Forge an admin token for subcommand `0x05`.
- Build a tiny VNM program with:
  - opcode `0x02` to load a 32-bit immediate into a VM register
  - opcode `0x07` to write that register into `g_pwn + 0x10 + i`
- Overwrite the diagnostic command buffer with `cat /home/ctf/flag > /opt/neuralchat/downloads/flag_dump\x00`.
- Trigger diagnostics. The engine runs the rewritten command as root via `system()`.
- Fetch `/api/download?file=flag_dump` and read the flag.
- Decisive insight: the admin token was not protecting anything because the server itself leaked both inputs to the secret derivation (`pid` and startup time), and the diagnostics VM already had a signed-offset write gadget aimed at the command string that `system()` later executes.

## 4. Dead Ends Worth Remembering

- Treating this as a classic memory-corruption-first pwn target was slower than checking the web-exposed telemetry. The hardening on `engine` is noisy, but the easier break is the logic flaw in admin-key derivation.
- The unauthenticated knowledge-upload over-read is exploitable, but it does not come with a clean read-back primitive on the raw engine side. Once `/api/download` and the deterministic admin key were both visible, the upload bug was the wrong main route.
- Admin subcommand numbering is shifted from the first static guess: `0x01` returns admin info, `0x04` reads the log tail, and `0x05` is the VNM-plus-`system()` path. Trying `0x00` just returns `Unknown admin command`.

## 5. Lessons to Reuse

- Signals to watch for:
  - a "secret" derived only from process-local values like PID, start time, or uptime
  - a status API that leaks those values directly or leaks enough to reconstruct them
  - a diagnostic or plugin VM that writes into a string later passed to `system()`
- Mitigation mix:
  - binary hardening (`PIE`, canary, `Full RELRO`, `SHSTK`, `IBT`) did not matter because the decisive bug was outside the usual memory-corruption path.
  - the presence of a frontend and raw endpoint changed the preferred route from local-ELF exploitation to protocol and application-state analysis.
- Reusable trick:
  - when an auth token uses `SHA256(timestamp || subcmd || payload || derived_secret)`, look for a separate status or monitoring endpoint that leaks the seed material for that `derived_secret`.
  - a signed-byte offset in a VM often reaches "just before the intended sandbox window"; here it extended a `g_pwn + 0x90` scratch area back into the live command buffer at `g_pwn + 0x10`.
- Should `patterns.md` be updated: no. The lesson is useful, but the exact combo of Flask status telemetry plus a VNM command-string overwrite is still challenge-specific.
