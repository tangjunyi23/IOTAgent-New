# CTF Pwn Methodology: ez_nc

**Date**: 2026-03-30
**Binary**: `ez-nc`
**Architecture**: `x86_64`
**Mitigations**: `NX`, `Full RELRO`, `PIE`, `No Canary`, `SHSTK`, `IBT`
**Vulnerability Class**: `format string in filename synthesis`
**Primitives**: `format-string-driven filename synthesis`, `remote binary recovery`, `static flag extraction`
**Reuse Tags**: `fmt`
**User-Provided ida-no-mcp Pseudocode**: no

## 1. Snapshot

- Goal: solve the remote-only service at `nc1.ctfplus.cn:35464` with no bundled ELF.
- Local artifacts used: a recovered copy of the executable at `/home/tankuku/timu/pwn/ez-nc/remote_bin.bin`, plus `file`, `checksec`, `strings`, and `readelf`.
- The shortest path was to recover the missing attachment first instead of pursuing `%n`, GOT writes, or PIE/libc leaks.

## 2. Ground Truth

- Runtime probing showed the prompt `Enter the filename to download: `.
- Sending `%45$s` returned `File content:\n` followed by an ELF header, proving attacker input is interpreted as a format string before the file open.
- Recovered ELF facts:
  - `file`: x86_64 PIE, dynamically linked, not stripped
  - `checksec`: Full RELRO, NX, PIE, no canary, SHSTK, IBT
  - `sha256`: `a7387a24811ccb38158a10139afbbdddc5eec1eef3d70467f8f3f99b38cb085d`
  - size: `16873` bytes
- `readelf -p .rodata` and `strings -a -tx` showed an embedded flag literal at offset `0x2008`:
  - `polarisctf{9c500a35-bd08-4ceb-a0b6-114ae396e647}`

## 3. Exploit Chain

- Stage 1: send `%45$s` as the requested filename.
- Stage 2: let the vulnerable formatter synthesize a stack-backed startup path and make `fopen` stream the current executable.
- Stage 3: save the ELF locally and extract the flag string from `.rodata`.
- Decisive insight: when user-controlled text is passed as the format string to `snprintf(dst, size, user_fmt)` and the result becomes a filename, deep positional `%s` often recovers `argv[0]` or a nearby startup path faster than any blind write path.

## 4. Dead Ends Worth Remembering

- Route skipped: `%n`-style writes or classical control-flow hijack.
- Why it was unnecessary: the service exposes a complete file-read primitive once the filename is format-controlled, and the binary itself already contains the flag.
- Earlier signal that pointed to the right path: `%45$s` immediately produced an ELF header, so attachment recovery dominated every more complicated route.

## 5. Lessons to Reuse

- Signals to watch for:
  - a remote-only file downloader with suspiciously short filename input
  - format directives that are partially blacklisted while positional `%s` survives
  - an error or success path that echoes the resolved filename after formatting
- Mitigation mix:
  - RELRO, PIE, SHSTK, and IBT were irrelevant because no code-reuse path was needed.
  - The missing canary also did not matter because exploitation never touched the return path.
- Reusable trick:
  - if a service lacks attachments but can be coerced into opening a stack-derived path through `%s`, recover the ELF first and treat static strings as part of the attack surface.
- Should `patterns.md` be updated: no. The generalized `snprintf(..., user_fmt) -> fopen` lesson is already present under `fmt`.
